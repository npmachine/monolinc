## 1. Goals & Scope

### What We're Building
A real-time text chat service. A minimal product where users can create rooms, join them, and exchange messages.

### MVP Success Criteria
- Two or more users can exchange messages in real time within the same room
- Messages persist across page refreshes
- Users can see who is currently online

### Out of Scope for MVP (Later)
- 1:1 Direct messages
- File / image attachments
- Message editing / deletion
- Notifications (Push, Email)
- Admin features
- Mobile app

## 2. Tech Stack

| Area | Choice | Reason |
|------|--------|--------|
| Language | Elixir | Concurrency, fault-tolerance |
| Web Framework | Phoenix 1.7+ | Real-time UI with LiveView |
| Real-time | Phoenix Channel | WebSocket-based chat |
| Online Status | Phoenix.Presence | Built-in distributed Presence |
| DB | SQLite (Ecto + Exqlite) | Simplicity for MVP, easy deployment |
| Auth | mix phx.gen.auth | Official Phoenix auth generator |
| Deployment | Fly.io | Elixir-friendly, free for small scale |

## 3. Data Models

### Users
```
users
  id            uuid, PK
  email         string, unique, not null
  username      string, unique, not null
  password_hash string, not null
  inserted_at   timestamp
  updated_at    timestamp
```

### Rooms
```
rooms
  id            uuid, PK
  name          string, not null
  slug          string, unique, not null   # URL identifier (e.g. "general")
  description   string, nullable
  created_by    uuid, FK → users.id
  inserted_at   timestamp
  updated_at    timestamp
```

### Messages
```
messages
  id            uuid, PK
  content       text, not null
  room_id       uuid, FK → rooms.id
  user_id       uuid, FK → users.id
  inserted_at   timestamp
  updated_at    timestamp
```

> `inserted_at` / `updated_at` are the default field names generated by Ecto's `timestamps()` macro

## 4. Feature Spec

### 4-1. Authentication

**Sign Up**
- Input: email, username, password
- Email uniqueness check
- Minimum password length: 8 characters

**Sign In / Sign Out**
- Session-based auth (phx.gen.auth default behavior)
- Redirect to room list after sign in

**Access Control**
- Unauthenticated users cannot access rooms → redirect to sign-in page

---

### 4-2. Rooms

**Room List**
- Display all available rooms
- Show name, description, and current member count for each room

**Create a Room**
- Input: name, slug, description (optional)
- Slug allows only alphanumeric characters and hyphens; used in the URL
- Any signed-in user can create a room

**Join a Room**
- Accessible via `/rooms/:slug`
- Non-existent slug → 404

---

### 4-3. Messaging

**Send a Message**
- Type in the input field and press Enter or click the Send button
- Empty messages are not allowed
- Maximum 2,000 characters

**Display Messages**
- Show sender's username, content, and timestamp
- New messages append to the bottom with auto-scroll
- Load the most recent 50 messages on room entry

**Real-time Sync**
- Broadcast instantly to all users in the same room via Phoenix Channel
- Channel topic: `room:{room_id}`

---

### 4-4. Online Presence — Post-MVP

> Displaying online users via Phoenix.Presence is deferred to a post-MVP phase

## 6. Phoenix Architecture

### Context Structure
```
lib/chat/
  accounts/         # User auth (phx.gen.auth)
    user.ex
    accounts.ex

  rooms/            # Room domain
    room.ex
    rooms.ex        # CRUD, business logic

  messaging/        # Message domain
    message.ex
    messaging.ex    # Save and query messages

lib/chat_web/
  channels/
    room_channel.ex         # Phoenix Channel
    user_socket.ex

  live/
    room_live/
      index.ex              # Room list
      show.ex               # Chat room (main)
      new.ex                # Create room
```

### Channel Event Definitions
```
# Client → Server
"new_message"     # Send a message
  payload: { content: string }

# Server → Client
"new_message"     # Broadcast message
  payload: { id, content, username, inserted_at }
```
